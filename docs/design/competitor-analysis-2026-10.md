# 竞品调研与产品规划补充建议（2026-10）

> 调研对象：国内 AI 标书生成 SaaS（公开官网/评测，2026-10 时点）。
> 结论服务于本仓库「投好标」SaaS 个人版的规划修订：对照 [product_mvp.md](../../product_mvp.md) 与当前代码实际，给出需要**补充**或**修改**的条目。
> 证据来源见文末链接。知乎/CSDN 部分横评带软文性质，涉及竞品具体参数（价格/字数）以官网为准。

## 2. 行业共识与用户痛点（评测/社区侧）

1. **主链路已同质化**：解析 → 评分点解析 → 大纲 → 正文 → 废标检查。谁都有，不构成卖点。
2. **2026 差异化主战场 = 「以标写标」**（历史标书风格学习）与**防雷同**：通用 AI 生成的内容模板化，不同投标人"撞内容"有**串标/废标合规风险**（知乎/网易多篇讨论，武汉科技局报道的头部产品也以"企业可上传往年标书学习写作风格"为核心卖点）。
3. **计费主流结构**：**解析+大纲免费做钩子，只在正文生成（最高价值环节）收费**；预充值点数（喜币）或"时长套餐+字数加油包"双轨；免费体验额度 8~10 万字。
4. **信任与合规是转化率杠杆**：标书是敏感商业材料，"数据隔离/不留存/不训练/私有化"被当成一级卖点反复宣传。
5. 图表自动生成（表格/流程图/甘特图）、企业资质自动填充，是小晓等产品的可感知差异化点。

## 3. 差距分析（按优先级，映射到当前代码）

### P0-1 计费点错位：扣费在"导出"，竞品在"正文生成"
- **现状**：注册送 10 万字，Word 导出按字数扣费（`chargeExportOnce`，内容指纹防重）。
- **问题**：① 扣费点在链条末端——解析、大纲、正文全部"免费"跑完，用户在导出前已消耗了平台绝大部分 AI 成本；② 导出失败/不导出的用户永远不付费；③ 与"注册送 10 万字"组合，轻度用户可能永久免费。
- **竞品共识**：解析/大纲免费做钩子，正文按字数收费。
- **建议修改 product_mvp 一期计费口径**：解析、大纲、查重、废标检查**免费**；**正文生成按输出字数扣 quotaChars**；**导出免费**（或仅去水印类增值）。技术上已就绪：`ai_call_stats` 埋点（次数/输入输出 token/字数）一期已落全，`content-generation` runner 的输出字数可实时计量扣减；把 `chargeExportOnce` 的闸门逻辑平移到正文生成完成时即可。
- **配套**：注册赠送额度建议降到 2~3 万字（正文口径），把"10 万字"改成营销话术里的"免费解析 N 份+试用正文 X 万字"。

### P0-2 「以标写标」/历史项目风格复用（差异化主战场）
- **现状**：「已有方案扩写」支持上传原方案（`originalPlanMarkdown*` 一整套字段），但仅限单项目内扩写；用户级"风格/素材"资产不存在（知识库已按个人版裁剪）。
- **竞品**：喜鹊"以标写标"、武汉报道的"上传往年标书学风格"是 2026 头部产品共同卖点。
- **建议**：把 README 计划 #3（强规则弱模型管道）与"以标写标"合并为一期后最优先项——**用户级「风格档案 + 常用章节库」**：
  - 上传 1~N 份历史标书 → 抽取章节结构与常用表述（`knowledge-base/extraction.ts` 的抽取管道是活代码，可复用）；
  - 生成正文时注入风格样本（few-shot）+ 章节库命中优先（规则管道）。
- 对个人写标人（我们的目标用户）这是**刚需**：他们靠复用过往项目吃饭。

### P0-3 防雷同/防串标：从内部计划升级为卖点
- **痛点**：内容模板化雷同 → 串标/废标风险（见第 2 节#2）。
- **已有基础**：README 计划 #2（多模型弹性分配）+ 标书查重引擎（14 张表的分析管道）+ 多 Key 池/按用户公平调度队列。
- **建议**：
  1. 多模型路由按用户/项目分散（计划 #2，防"同项目多份标书同模型同腔调"）；
  2. 查重新增"**跨我的历史项目比对**"——现在查重只比对一次上传的文件集，加一个"与本人历史导出内容比对"的入口即可让"防串标"成为可展示的报告；
  3. 产品文案显性承诺"差异化生成，降低撞标风险"。

### P1-4 个人素材库（以个人版形态找回被裁剪的知识库）
- **现状**：企业知识库/资质库/人员库已按 MVP 决策裁剪（对个人版正确）；但"素材复用"是竞品验证过的留存核心。
- **建议**：不做企业库，做**「我的素材库」极简版**——项目无关的用户级文档/片段存储（上传→解析→生成时按需引用）。技术上 `knowledge-base/store.ts`（现仍被 content-generation 读共享文档）与抽取管道可支撑，UI 复用格式管理的样式体系即可。配合二期已有的"项目归档打包下载"（API-31），形成"归档→入库→复用"闭环。

### P1-5 投标信息卡（轻量版"企业资质自动填充"）
- **现状**：每个项目手动维护 bidderName/代称/全局事实；竞品（小晓）有"自动填充企业资质"。
- **建议**：用户级「投标信息卡」（公司全称/简称/统一社会信用代码/常用承诺表述），新项目默认带入，全局事实页可改。个人写标人服务多家委托方时尤其需要（可存多张卡，项目绑定一张）。改造成本低：`TechnicalPlanGlobalFactGroup` 管道加一个"从用户档案初始化"入口。

### P1-6 正文图表主动生成
- **现状**：导出链路已支持 Mermaid 渲染（mermaid.ink+缓存）与 HTML 表格，但**生成端**提示词不主动产图表。
- **建议**：`content-generation` runner 的章节提示词按节引导"适处插入 mermaid 流程图/表格"（现有 markdown 管道零改动），对齐小晓的可感知差异化。低成本，感知强。

### P1-7 计费双轨：字数 + 时长套餐
- **竞品**："时长套餐+字数加油包"（IT之家盘点）与纯预充值（喜鹊）并存。
- **建议**：`quota_orders` 已有 planKey/amountCents 结构，`QuotaPlan` 增加时长类 SKU（月度：不限正文次数/更高并发优先级）；配合 P0-1 的计费点迁移一起设计，避免两次改价。

### P2-8 信任产品化：安全承诺页 + 开源双轨
- 标书敏感 → "数据隔离（user_id 硬隔离，代码真实存在）、不训练、可自部署"应产品化为注册页/协议/落地页文案。
- **AGPL 双轨策略**：竞品闭源 SaaS 与私有化报价高企；本仓库开源可自部署本身就是差异化——落地页（FE-18）明确"企业可自行私有化部署，源码可审计"，与 SaaS 版互不挤兑。

### P2-9 标讯订阅/中标率预测：观察项，不建议自建
- 剑鱼/千里马以 13 年数据壁垒做标讯入口，自建无优势；"中标率预测"缺乏数据支撑，易变伪功能。
- 务实替代：① 项目卡片加"开标时间"字段+到期提醒（纯本地提醒，成本极低）；② 未来若做集成，接第三方标讯 API 而非自建爬虫。

### P2-10 废标检查报告化
- 检查已是标配，差异化在**交付物**：检查结果一键导出为 Word/PDF 报告（给用户的委托方/内部汇报用）。`export/docxBuilder` 管道可复用，属低 hanging fruit。

## 5. 明确不建议跟的

- **多人协作/团队权限**：竞品短板，但与个人版定位相反，不跟。
- **中标概率预测**：无数据支撑，做出来就是伪功能；先做评分对照自检。
- **自建标讯爬虫**：数据壁垒打不过剑鱼/千里马，合规风险高。
- **私有化报价体系**：开源版天然可自部署即可，不做企业级交付承诺（人力不支持）。
