# Web 架构

## 1. 组件

- `client/`：React 19 + Vite 7，只负责 UI、请求编排和 SSE 展示。
- `server/`：Fastify 5 权威后端，负责鉴权、权限、文档解析、AI 请求、后台任务、导出和存储。
- `server/prisma/schema.prisma`：PostgreSQL schema 单一真相。
- Nginx：托管前端静态文件并反向代理 `/api` 和 SSE。
- PM2：使用项目本地 `tsx` 运行 `server/src/index.ts`。

## 2. 请求与数据边界

```text
Browser
  ├─ /             → Nginx → client/dist
  └─ /api + SSE    → Nginx → Fastify → Prisma → PostgreSQL
```

客户端不保存 API Key，不解析或导出权威文档。所有跨网络参数均由服务端重新校验。

## 3. 鉴权与权限

- JWT 分为两种用途：`purpose=access` 的正式会话令牌有效期为 7 天，用于常规受保护接口；`purpose=initial-password-change` 的受限令牌有效期为 10 分钟，只能用于首次改密接口，不能访问业务接口。为兼容升级，旧正式令牌未携带 `purpose` 时仍按正式会话处理。
- `mustChangePassword` 是用户的首次改密状态：全新安装时创建的默认管理员为 `true`，首次改密成功后原子更新为 `false`；已有用户和普通注册用户默认为 `false`。状态为 `true` 时不会签发正式会话令牌。
- 用户角色为 `admin` 或 `user`。
- 普通用户通过模块列表获得功能权限。服务端可授予模块白名单为 `template-settings`、`knowledge-base`、`bid-check`、`docs`、`faq`。
- 默认开放模块为仪表盘、标书生成和设置；用户管理与提示词管理仅管理员可用。
- 用户管理与提示词写操作仅管理员可用。
- 项目作用域 API 使用 `X-Project-Id`，服务端校验项目归属。
- 权限在服务端每次请求时生效，前端通过 `/api/me` 定时刷新菜单。

## 4. 模块边界

- 标书生成：技术方案、已有方案扩写、投标计算器入口、响应与偏离表工作台。
- 格式管理：我的模板、新建模板、导出格式和共享模板。
- 知识库：方案模板库、工具模板库、公司资质库、人员资质库。
- 标书检查：标书查重和废标项检查。
- 使用文档与 FAQ：数据库文章、Markdown 渲染、管理员编辑和用户反馈。
- 管理模块：用户管理、提示词管理、基本设置。

“投标计算器”是标书生成下的评分辅助入口，定位为汇总综合报价、技术评分和商务评分规则，辅助计算标书最终得分；当前仍保持开发中提示，不在架构上承诺完整评分引擎已经落地。

## 5. 数据范围

- 用户域：用户、个人设置、平台配置、提示词、FAQ、导出模板、使用文档文章。
- 项目域：技术方案、已有方案扩写、响应与偏离表、标书查重、废标检查及后台任务。
- 公司共享域：知识库、工具资产、公司资质和人员资质。
- 大文件落在服务端运行数据目录，数据库只保存路径和结构化元数据。

## 6. 主题、品牌与开源归属

- 初始系统名称来自服务端默认配置：`易标投标工具箱web版`。
- 登录页、顶栏和导出元数据使用系统设置中的名称和 Logo；管理员可在“设置 - 基本设置”中修改。
- 客户端通过 `ThemeProvider` 管理主题，主题值为 `light` 或 `soc-dark`，存储键为 `yibiao_ui_theme`。
- `soc-dark` 主题通过 `html[data-theme='soc-dark']` 作用域覆盖历史浅色样式，尽量不改动各业务组件的结构。
- Markdown 文档和 Mermaid 预览会读取当前主题，保证使用文档在深色模式下可读。
- 开源说明组件在登录页和应用界面展示当前修改版源码、原始项目、AGPL、NOTICE 和作者归属。部署方可通过 `VITE_SOURCE_REPOSITORY_URL` 指向正在运行版本对应源码。

## 7. 使用文档种子

- 静态 Markdown 原稿位于 `server/prisma/seed-docs/`。
- 前端 `client/public/docs/` 保留同名静态文档和图片资源，便于 Markdown 图片路径稳定访问。
- 数据库文章由 `server/prisma/seed-docs.ts` 写入 `docs_articles`。
- seed 使用固定 id 幂等 upsert，刷新标题和正文，不覆盖管理员调整过的排序。

## 8. AI 与通用模型互通

AI 配置与真实密钥只存在服务端，浏览器端不保存 API Key。文本模型、生图模型和 Agent 运行时通过服务端配置读取服务商、模型名称、Base URL 和密钥，再由后端或本地 AI Proxy 发起调用。

部署方可以按安全策略选择三种互通方式：

1. 连接公网通用大模型服务：服务端出网访问模型 API，适合快速启用，但需要确认招标文件、客户资料和生成内容是否允许发送给外部服务。
2. 连接企业统一模型网关：通过内网或受控出口访问 OpenAI-compatible 网关，便于做审计、限流、密钥轮换和模型统一管理。
3. 连接本地或私有化模型服务：将 Base URL 指向内网推理服务，数据流转范围更可控，但需要自行保障模型能力、上下文长度和并发性能。

服务端的 AI Proxy 会把平台配置转换为运行时可用的模型请求，避免各业务模块直接持有密钥。日志和诊断输出只应包含服务商、模型名、Base URL 连通性和错误摘要，不应输出完整 API Key。

## 9. Web 运行边界

Web 版以浏览器、HTTP API、SSE 进度推送、PostgreSQL 和服务端运行数据目录为边界。前端所有业务能力都应通过 `/api` 调用服务端，不直接读写数据库、文件系统或模型密钥。

运行时数据边界：

- 数据库保存结构化业务数据、权限、配置、文档文章和任务元数据；
- 上传文件、导出结果、文档解析中间文件保存到服务端运行数据目录；
- `.env`、数据库备份、上传目录、日志和客户文件由部署环境管理，不进入源码仓库；
- Nginx 只暴露前端静态资源、`/api` 和必要的 SSE 路由，数据库与后端内部端口不应直接暴露到公网。

## 10. SaaS 租户与协作目标模型（待实施）

本节定义后续 SaaS 化的目标边界，不代表当前代码已经实现租户隔离或项目成员授权。当前 `User.role`、`Project.ownerId`、公司共享资源和模块权限仍按本节前述现状运行；在服务端完成数据迁移和授权改造前，不应把当前部署视为多租户安全边界。

### 10.1 租户与用户成员关系

- 租户类型为个人空间或组织空间。每个用户在任一时刻只属于一个租户；一个组织租户可以有多名成员。
- 新用户注册时创建个人空间，并成为该空间所有者。个人空间可升级/转换为组织空间，或在接受组织邀请时迁入组织；迁移前明确处理其个人数据归属，不能静默转移或让原所有者失去数据。
- 概念数据模型：`Tenant` 保存租户类型、名称、状态和所有者；`TenantMembership` 保存用户、租户、租户角色及成员状态。数据库需对用户当前有效成员关系施加唯一约束；邀请在接受前不改变用户的当前租户。
- 组织通过邀请加入成员。被邀请者已有其他租户时，必须先明确迁移/转移个人数据，再接受邀请；不支持同一账号同时跨租户访问业务数据。
- 唯一租户所有者不能被普通管理员移除或降权。转移所有权须由现所有者确认；租户必须始终保有一名所有者。

### 10.2 角色与授权层次

授权分为平台、租户和项目三个层次，彼此不可替代：

| 层次 | 角色 | 权限边界 |
| --- | --- | --- |
| 平台 | 平台管理员 | 管理平台级账号、运行配置和平台服务；不因平台角色自动获得客户项目内容访问权。 |
| 租户 | 所有者 | 管理租户、成员与租户资源；转移所有权或关闭租户。 |
| 租户 | 管理员 | 管理成员和租户级设置/资源；不能转移所有权，也不因租户角色自动读取项目内容。 |
| 租户 | 成员 | 使用被授予的租户资源，以及显式加入的项目。 |
| 项目 | 管理员 | 管理项目成员与项目设置，并可读写项目内容。项目创建者自动取得此角色。 |
| 项目 | 编辑者 | 读取、修改项目内容，上传文件，运行生成/检查任务并导出。 |
| 项目 | 查看者 | 只读项目内容；不得修改内容、上传文件或启动任务。允许下载/导出前，产品需按数据泄露风险明确配置策略。 |

- 用户现有的 `admin`/`user` 平台角色与租户角色分离；现有模块白名单只控制功能入口，不授予任何租户或项目的数据访问权。
- 项目数据采用显式项目成员授权。成为租户所有者/管理员或租户成员本身不授予项目正文、招标文件、生成结果和文件下载权限；需要项目管理员单独加入项目。平台运维同样默认无客户内容访问权。
- 所有项目 API、SSE 订阅、任务状态/控制、导出和文件下载均须在服务端校验“当前用户有效租户成员 + 项目属于该租户 + 当前用户具有所需项目角色”。不能信任客户端传入的 tenant/project/user id，也不能只依赖隐藏菜单。
- 批量操作、后台任务和 SSE 事件必须沿用启动请求时校验过的租户与项目作用域；任务运行期间成员被移除或项目被转移时，应拒绝后续访问并停止/隔离未完成工作。

### 10.3 资源归属与默认可见范围

资源归属显式区分平台、租户、项目和个人四个作用域。可共享资源同时记录创建者与所属租户；“共享”只在所属租户内生效，不等于跨租户或全平台公开。

| 资源 | 默认归属 | 访问规则 |
| --- | --- | --- |
| 招标文件、技术方案、响应偏离、查重/废标结果、任务和导出物 | 项目 | 仅显式项目成员按项目角色访问。 |
| 文档知识库、工具/公司资质、人员资质 | 租户 | 租户内共享为默认；允许创建者将资源设为个人私有。 |
| Word 模板、个人偏好、个人草稿 | 个人 | 仅本人访问；用户可选择发布为所属租户共享资源。 |
| 用户账号凭证、会话和个人设置 | 个人 | 仅本人及必要的平台身份管理流程可访问。 |
| 系统名称、平台级模型配置/密钥、全站提示词和内置帮助文档 | 平台 | 由平台管理员维护；不暴露密钥给租户成员。若未来支持租户自带模型配置，应另建租户级配置并与平台配置分开授权。 |
| 用户反馈 | 个人提交、平台处理 | 提交者与平台授权人员按反馈流程访问；不得因租户共享而默认公开。 |

资源列表、搜索、下载、预览、删除、关联引用和后台处理必须使用相同的作用域规则。切换资源可见范围须校验操作者权限；降为私有时不可破坏已有项目的引用，删除或移出租户时须阻止悬空引用或执行明确的迁移流程。

### 10.4 项目协作生命周期

1. 用户在当前租户内创建项目，项目记录所属 `tenantId` 和创建者，创建者自动成为项目管理员。
2. 项目管理员邀请同租户成员并授予项目管理员、编辑者或查看者角色。外租户用户不可直接加入。
3. 请求上下文由服务端从已验证会话解析用户和租户，再以数据库关系确认项目归属和成员角色；前端的当前租户/项目选择仅用于请求路由，不构成授权凭证。
4. 移除成员后立即拒绝新请求及 SSE 重连；已运行任务要按任务状态安全取消或完成后隔离结果。项目移交、归档和删除须保留审计记录并处理运行文件。

### 10.5 现有数据迁移规则

- 为现有每个用户创建个人租户，并将该用户拥有的项目及项目级数据归入其个人租户；原 `Project.ownerId` 对应用户成为项目管理员。迁移应幂等，并先做关系一致性检查。
- 用户配置、个人模板和个人反馈保留原用户归属。原 `isShared` 模板不再解释为“全站共享”：迁移到创建者个人租户的租户共享范围；若创建者缺失或归属不确定，进入待处理区而非扩大公开范围。
- 当前知识库、工具/公司资质和人员资质没有明确租户/创建者归属字段，且按公司级共享。它们无法安全地自动归入某位用户的个人租户；迁移时放入受限的待分配区，由部署管理员确认目标租户后再开放。不得复制到每个租户或默认让所有租户继续可见。
- 平台配置、系统提示词和内置文档保留平台作用域。现有平台管理员账号仍是平台管理员身份，但不因此自动成为各个人租户成员或取得项目内容访问权。
- 上线迁移前备份数据库和文件目录；先运行只读盘点/校验，再在维护窗口分批迁移并验证项目数、资源数、文件可达性、成员关系与越权拒绝行为。迁移失败必须可重试，且在验证完成前保留回滚备份。

### 10.6 实施顺序与验收边界

先建立租户/成员/项目成员数据模型及迁移，再实现统一服务端授权上下文，随后逐个改造项目 API、SSE、后台任务、文件路径和共享资源查询，最后开放邀请与管理界面。任何阶段都不得以客户端过滤代替后端隔离。

租户隔离的最低验收条件是：跨租户不能枚举或读取项目、知识库、资质、模板、文件、任务或 SSE 事件；同租户但未加入项目的成员不能读取项目数据；移除成员后其旧会话不能继续访问相关数据；普通租户管理员不能读取项目内容，除非显式加入该项目。
